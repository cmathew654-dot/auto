## Directory Purposes

**Root Level Source Files:**
- Purpose: Core application modules (TypeScript, no src/ subdirectory)
- Contains: Parsing, schema, UI rendering, styles, browser helper
- Key files: `main.ts` (entry), `holdings-csv-parser.ts` (CSV→data), `review-export-surface.ts` (UI), `paste-conductor.ts` (packets)

**scripts/:**
- Purpose: Build automation, local development, testing
- Contains: esbuild setup, dev server, test runners, diagnostics
- Key files: `build-demo.mjs` (compile to demo-dist), `serve-demo.mjs` (run local server)

**demo-dist/:**
- Purpose: Generated browser demo (ES2020 modules)
- Contains: Compiled `.js` files, `index.html` entry
- Generated by: `npm run build:demo`
- Committed: Yes (for GH Pages deployment)

**.test-dist/:**
- Purpose: Generated compiled tests
- Contains: `.cjs` files after TypeScript compilation
- Generated by: `npm test`
- Committed: No

**portfolio/:**
- Purpose: Project artifacts, articles, design narratives
- Contains: `intake-reconstruction.html` (original interview)
- Used by: Demo page links to "how-it-started" reconstruction

**sample-data/:**
- Purpose: Test data (CSV exports for manual testing)
- Contains: Fixture CSVs from various custodians
- Used by: `npm run test:portable`, manual demo testing

**src-tauri/:**
- Purpose: Optional Tauri desktop app shell
- Contains: Rust frontend, capability permissions, icons
- Used by: `npm run desktop:dev` / `npm run desktop:build`

**docs/:**
- Purpose: Documentation (project history, design decisions)
- Contains: `how-it-started.md` (origin story)

## Naming Conventions

**Files:**

| Pattern | Example | Use |
|-|-|-|
| `kebab-case.ts` | `holdings-csv-parser.ts` | Core modules |
| `kebab-case.test.cjs` | `holdings-csv-parser.test.cjs` | Tests (co-located) |
| `PascalCase.md` | `ARCHITECTURE.md` | Documentation |

**Directories:**

| Pattern | Example | Use |
|-|-|-|
| `kebab-case/` | `demo-dist/`, `src-tauri/` | Build output, feature folders |
| `dot-prefix/` | `.planning/`, `.test-dist/` | Generated/cache |

**Code Style:**

- Camel case for functions and variables: `parseHoldingsCsvToIngestionFile`, `buildAccountPreflightSummary`
- PascalCase for types and interfaces: `HoldingRecord`, `EmoneyFillPacket`, `ReviewStatus`
- SCREAMING_SNAKE_CASE for constants: `HEADER_ALIASES`, `ALLOWED_FIELDS`, `MANUAL_REVIEW_REQUIRED_CODES`
- Kebab case for CSS class names: `ledger-shell`, `ledger-load-panel`, `workflow-stepper`

## Where to Add New Code

**New Validation Rule (CSV Parsing):**
- Primary code: `holdings-csv-parser.ts` (add condition in row validation loop, create Issue)
- Schema update: `holdings-schema.ts` (add Issue code to union)
- Tests: `holdings-csv-parser.test.cjs` (add test case in existing suite)
- Pattern: All validation happens during `parseHoldingsCsvToIngestionFile()`; issues flow through `HoldingRecord.issues` array

**New Eligibility Gate:**
- Primary code: `review-export-surface.ts` in `getHoldingEligibility()` function
- Add condition, append to `blockedIssueCodes`, add friendly label in `toFriendlyIssueLabel()`
- Tests: `review-export-surface.test.cjs`
- Pattern: Gates are checked in eligibility function; render via `buildAccountPreflightSummary()`

**New UI Component:**
- Primary code: `review-export-surface.ts` (add element creation and event listeners)
- Styles: `ledger-styles.ts` (add CSS rules using existing variables)
- Pattern: Imperative DOM creation (no frameworks); attach listeners to elements; use CSS custom properties for colors/spacing

**New eMoney Fill Field:**
- Primary code: `paste-conductor.ts` (add field to `PasteConductorFieldName` union, `ALLOWED_FIELDS` array)
- Bookmarklet update: `emoney-browser-helper.ts` (add selector in `SELECTORS` object, update form fill logic)
- Tests: `paste-conductor.test.cjs` and `emoney-browser-helper.test.cjs`
- Pattern: Fields serialized in `EmoneyFillPacket.holdings`, then filled by bookmarklet using DOM selectors

**New CLI/Script:**
- Location: `scripts/` directory (use `.mjs` for ES modules)
- Pattern: Use Node built-in APIs (fs, child_process, path); no external npm packages for scripts
- Example: `scripts/build-demo.mjs` shows pattern (spawn tsc, post-process, write HTML)

## Build & Test Outputs

**Development:**
```bash
npm run build:demo          # → demo-dist/ (esbuild-free, TypeScript only)
npm run start:demo          # → http://localhost:3456 (serve-demo.mjs)
npm test                    # → Runs .test.cjs files via Node test runner
npm run typecheck           # → Validates TypeScript without emit
```

**Production:**
```bash
npm run build:portable      # → Single HTML file with CSP
npm run desktop:build       # → Tauri app executable (Windows, macOS, Linux)
```

## Import Patterns

**Within source code:**

```typescript
// Relative imports for co-located modules
import { parseHoldingsCsvToIngestionFile } from './holdings-csv-parser';
import type { HoldingsIngestionFile } from './holdings-schema';

// Type imports use 'type' keyword (not emitted in output)
import type { HoldingRecord, Issue } from './holdings-schema';
```

**In built demo-dist/:**

- Post-process step in `build-demo.mjs` rewrites all relative imports to include `.js` extension
- Allows ES2020 modules to load via browser script tags without bundling

## Testing Strategy

- Tests are Node CommonJS modules (`.test.cjs` files)
- Run via `node --test` (Node 18.0.0+)
- No external test frameworks (assertions use Node `assert` module)
- Tests import compiled `.cjs` output from `.test-dist/`
- Each module has co-located test file (e.g., `holdings-csv-parser.ts` → `holdings-csv-parser.test.cjs`)
