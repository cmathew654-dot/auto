  <action>
Create `demo-sample.ts` exporting `export const DEMO_SAMPLE_CSV: string` — a joined string array in the same style as the current `SAMPLE_CSV_INPUT` in main.ts (lines 21-26), using the same header the parser already understands: `Account Description,Account Number,Owner,Last Updated,Symbol,Description,Quantity,Price,Cost Basis,Value,Asset Class`.

Constraints on the sample content:
- SINGLE account only. The fill packet is built per account (`toAssistantPayloadForAccount` / `buildEmoneyFillPacket` in review-export-surface.ts + paste-conductor.ts); a multi-account sample would fork the one-click demo flow. Use one account: description `Demo Household - Taxable Brokerage`, account number `900000001`, owner `Demo Household`.
- Everything synthetic (SMPL-03): NO real tickers (no AAPL/MSFT/GOOG/VTI — the current sample and `sample-data/sample-holdings.csv` both use real ones). Use fabricated four-letter symbols such as `DMOA`, `DMOB`. Fabricated account number, fabricated owner, round fabricated dollar values.
- Verdict mix required in a single run (SMPL-01), derived from the real logic in `getHoldingEligibility` (review-export-surface.ts lines 88-120):
  - **ok / eligible**: 2 clean rows (`DMOA`, `DMOB`) with a symbol, nonzero quantity, and a parseable cost basis. These produce no issues and are export-eligible.
  - **review (manual-review gate, SMPL-02)**: one cash row — symbol `$CASH$`, description `CASH`, blank quantity, price `$1.00`, blank cost basis, asset class `Cash`. The parser emits `CASH_SPECIAL_HANDLING` (holdings-csv-parser.ts ~line 391), which is in `MANUAL_REVIEW_REQUIRED_CODES`, so it is withheld until the override checkbox is ticked. This is the row the override control gates.
  - **block (hard, not override-able)**: one row with NO lookup key — blank `Symbol`, description `UNIDENTIFIED SECURITY POSITION`, real quantity/price/value. `getHoldingEligibility` pushes `MISSING_LOOKUP_KEY` for it, and no override clears that.

Note on the blocked row: it must survive parsing as a holding record, not be dropped as an empty line. Verify with the Task 2 test. If a fully blank Symbol causes the row to be skipped by the parser, use a symbol that normalizes to empty (e.g. `-`) rather than weakening the block — do NOT switch to a blocking issue code, since the parser never emits `blocking: true` anywhere today (`toIssue` defaults blocking to false and no call site passes true).

Add `"demo-sample.ts"` to the `include` array in `tsconfig.test.json` so the test build emits `.test-dist/demo-sample.js`.

Add a short file header comment stating the data is fabricated and exists to exercise the ok/review/block gates.
