<task type="auto">
  <name>Task 2: Add label-driven runDemoFill to paste-conductor.ts</name>
  <files>paste-conductor.ts</files>
  <action>
Add to `paste-conductor.ts` (alongside the existing exports, NOT inside `EMONEY_FILL_BUTTON_SCRIPT`):

```ts
export function findFieldByLabel(root: ParentNode, labelText: string): HTMLInputElement | null;
export interface DemoFillProgress { rowNumber: number; ticker: string; }
export async function runDemoFill(
  root: HTMLElement,
  packet: EmoneyFillPacket,
  opts?: { onRow?: (p: DemoFillProgress) => void; stepDelayMs?: number }
): Promise<{ filledCount: number }>;
```

`findFieldByLabel`: iterate `root.querySelectorAll('label')`, normalize each label's `textContent` (trim + lowercase + collapse whitespace), compare to the normalized target, and resolve the field via `htmlFor` → `root.querySelector('#'+id)` (or `ownerDocument.getElementById`), falling back to a descendant `input` inside the label. Return null when no label matches. Matching is on the visible label text only — do not query by input id, name, or placeholder (DEMO-04).

`runDemoFill`: for each holding in `packet.holdings`, in order:
1. set Ticker, CUSIP, Units, Cost Basis via `findFieldByLabel(root, 'Ticker' | 'CUSIP' | 'Units' | 'Cost Basis')`, assigning `.value` and dispatching bubbling `input` and `change` events (reuse the same event-firing approach the bookmarklet script uses so the panel's handlers see real events);
2. locate the `Add a Holding` button by visible button text (normalized `textContent` match, same normalization as above) and click it;
3. call `opts.onRow`, then `await` a small delay (`stepDelayMs`, default ~250ms) so a visitor can watch rows land one at a time.

Throw a descriptive `Error` if a labeled field or the Add a Holding button cannot be found. Return `{ filledCount }`.

Hard constraints:
- Do NOT modify `EMONEY_FILL_BUTTON_SCRIPT`, `buildEmoneyFillBookmarklet`, `buildEmoneyFillButtonScript`, or `isApprovedEmoneyLocation`. The real bookmarklet path and its eMoney-host guard stay exactly as shipped; `runDemoFill` is a separate, demo-only entry point that deliberately has no host guard because it only ever drives an element the demo page itself created.
- `runDemoFill` must never look for or click a Save button. Save stays a human click (DEMO-08).
- Reuse the existing `EmoneyFillPacket` / `EmoneyFillPacketHolding` types; do not define a parallel packet shape.
  </action>
